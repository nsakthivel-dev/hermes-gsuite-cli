HERMES GSuite CLI Privacy Policy

This Privacy Policy describes how HERMES GSuite CLI (“HERMES”, “we”, “our”, or “the software”) accesses, handles, processes, and stores user information and Google Workspace user data when you install and operate the command-line application.

1. What HERMES CLI Is

HERMES GSuite CLI is an open-source, client-side command-line interface written in Python and distributed via PyPI as hermes-cli. It enables individual developers, system administrators, and command-line users to interact with their own Google Workspace services (such as Gmail, Google Calendar, Google Sheets, Google Docs, Google Meet, Google Forms, and Google Tasks) directly from their local terminal, with optional Gemini AI-powered workflows.

HERMES GSuite CLI is not a software-as-a-service (SaaS) web application and does not run a central backend database, authentication proxy, or server-side data processing infrastructure. All operations are initiated locally by the user.

2. What Google User Data May Be Accessed

HERMES CLI only accesses Google Workspace data corresponding to the specific commands executed by the user and the OAuth 2.0 permissions explicitly granted by the user on Google's consent screen. Depending on the commands used, this may include:

  • Gmail Data: Message metadata (sender, recipient, subject, timestamp), message bodies, thread identifiers, drafts, and label information when executing commands such as hermes gmail list, hermes gmail send, or hermes inbox.
  • Google Calendar Data: Calendar identifiers, event titles, descriptions, start/end dates and times, attendee lists, and event recurrence rules when executing commands such as hermes calendar list, hermes calendar today, or hermes calendar create-event.
  • Google Sheets Data: Spreadsheet metadata, sheet names, cell values, and ranges when running commands such as hermes sheets read or hermes sheets write.
  • Google Docs Data: Document metadata, structural elements, and document text content when running commands such as hermes docs read or hermes docs append.
  • Google Meet Data: Meeting space identifiers, configuration settings, and conference links when generating meeting rooms via hermes meet create.
  • Google Forms Data: Form schemas, questions, and respondent submission records when running hermes forms responses.
  • Google Tasks & Contacts: Task lists, task items, and basic contact information when explicitly requested by corresponding service commands.

3. Why Google User Data Is Accessed

HERMES GSuite CLI accesses Google Workspace data solely to execute the specific, user-initiated commands entered in the terminal. Examples include displaying upcoming appointments on your terminal screen, sending an email draft composed in your local editor, reading tabular data into a local CSV format, or summarizing email messages at your direct request.

HERMES CLI never accesses user data in the background without explicit user command invocation, does not scrape data for commercial advertising, and does not conduct secondary analysis or marketing profiling.

4. How OAuth 2.0 Authorization Works

HERMES GSuite CLI integrates with Google's official OAuth 2.0 Installed/Desktop Application flow (via the official google-auth-oauthlib Python library):

  1. When you invoke hermes auth login, HERMES starts a temporary local loopback webserver (on localhost) and launches your default web browser to Google's official consent page at https://accounts.google.com/o/oauth2/auth.
  2. You authenticate directly with Google. HERMES CLI never prompts for, observes, or has access to your Google password or two-factor authentication credentials.
  3. You are presented with Google's OAuth consent screen detailing the exact scopes requested by HERMES CLI. You explicitly decide whether to grant or deny access.
  4. Upon authorization, Google sends an authorization code to the local loopback server, which exchanges it with Google's token endpoint (https://oauth2.googleapis.com/token) for a short-lived access token and a refresh token.
  5. Each user authorizes their own Google account independently. HERMES CLI does not use a shared master account.

5. How Access & Refresh Tokens Are Handled

OAuth access tokens are short-lived credentials used to authenticate HTTPS requests directly from your machine to official Google API endpoints. When an access token expires, HERMES GSuite CLI uses the stored refresh token to request a refreshed access token directly from Google's token endpoint, without requiring you to re-authenticate manually in the browser.

6. Where Credentials and Tokens Are Stored

All credentials and tokens are stored strictly on the user's local file system under the user's operating system user profile:

  • OAuth Tokens: Stored at ~/.config/gsuite-cli/token.json (or %USERPROFILE%\.config\gsuite-cli\token.json on Windows). This file contains your issued access token, refresh token, token expiration timestamp, and granted scopes.
  • Client Secrets / Credentials: Stored at ~/.config/gsuite-cli/credentials.json, or loaded from user-specified environment variables (HERMES_GOOGLE_CLIENT_SECRET).
  • Configuration: Stored at ~/.config/gsuite-cli/config.yaml and optional runtime configurations at ~/.hermes/config.yaml.

These files are protected by standard local operating system file permissions. User A on a multi-user machine cannot read User B's tokens or configuration unless granted administrative root privileges on that host.

7. How Local Cache Data Is Handled

To enhance performance and reduce redundant Google API requests, HERMES CLI utilizes a local disk cache implemented with Python's diskcache library:

  • Cache Location: Stored strictly in ~/.cache/gsuite-cli/ (or %USERPROFILE%\.cache\gsuite-cli\ on Windows).
  • Cache Keys: Keys are generated using cryptographic hashes (MD5) of command parameters to maintain predictable local lookups.
  • Expiration (TTL): Cached data expires automatically according to a configurable Time-To-Live (default: 300 seconds / 5 minutes).
  • Purging: Users can inspect cache metrics or wipe the cache entirely at any time using hermes cache stats and hermes cache clear.

8. Transmission of Data to Third Parties

HERMES CLI does not operate any central server, telemetry collector, analytics tracker, or proxy service. No Google user data, credentials, tokens, or command inputs are transmitted to the maintainers of HERMES CLI or to any unrelated third-party servers.

Network communication occurs exclusively between your local machine and:

  1. Google APIs (*.googleapis.com): Required to perform your Google Workspace commands.
  2. Google Gemini API (generativelanguage.googleapis.com): Only when you explicitly use AI features, as detailed in Section 9 and Section 10 below.

9. How Gemini / AI Functionality Is Used

HERMES GSuite CLI integrates Google Gemini (using the official Google GenAI SDK) to provide natural-language assistance, email summarization, draft generation, and intelligent schedule queries.

Direct vs. AI Execution: The vast majority of HERMES commands (such as hermes gmail list, hermes calendar list, hermes sheets read, hermes docs list) are purely deterministic and communicate directly with Google Workspace APIs without any AI involvement.

10. Transmission of User Data to AI Services

When—and only when—a user explicitly invokes an AI-powered command (such as hermes ai ask “...”, hermes ai summarize, hermes ai compose, or hermes calendar smart-create):

  • The user's input prompt, along with the specific Workspace text requested to be summarized or analyzed (for example, the subject lines or body text of recent emails being summarized), is transmitted directly from the user's terminal to Google's Gemini API at https://generativelanguage.googleapis.com/.
  • Requests are authenticated using the user's own Gemini API key (supplied via the GEMINI_API_KEY environment variable or configured via hermes config set ai.gemini_api_key).
  • Data transmitted to Google's Gemini API is processed under Google's Generative AI Terms of Service and Google's Developer API policies. HERMES CLI does not save or transmit AI interaction prompts to any secondary server.

11. Data Retention

Because HERMES CLI does not operate an external database or backend server, the software itself retains no centralized user data. All data retained by the CLI exists solely on your local hard drive in the configuration and cache folders specified in Sections 6 and 7, subject to the local TTL and user deletion.

12. Data Deletion

Users maintain full control over their local data and can delete it at any time:

  • To Revoke & Delete Tokens: Run hermes auth logout. This command revokes the active token online with Google's revocation endpoint and securely unlinks/deletes ~/.config/gsuite-cli/token.json.
  • To Wipe Local Cache: Run hermes cache clear or delete the ~/.cache/gsuite-cli/ directory.
  • To Completely Remove Application Footprint: Delete the local directories ~/.config/gsuite-cli, ~/.cache/gsuite-cli, and ~/.hermes.

13. User Control & Revocation of Google Permissions

You may revoke HERMES CLI's authorization to access your Google account at any moment through Google's centralized account security interface:

  1. Navigate to Google Account → Third-party apps & services.
  2. Select HERMES GSuite CLI (or the custom Desktop Client ID configured for your project).
  3. Click Delete all connections that you have with HERMES GSuite CLI.

Once revoked, all outstanding access and refresh tokens are immediately invalidated by Google, preventing any further API calls from the CLI until you explicitly perform a new login flow.

14. Security Practices

HERMES GSuite CLI adheres to security-by-design principles:

  • All API network calls use encrypted TLS/HTTPS (port 443).
  • Zero secret bundling: The distributed PyPI package contains no hardcoded Google client secrets, user tokens, or proprietary API keys.
  • Bring Your Own Credentials (BYOC): Users control their own Google Cloud Project and OAuth Desktop client credentials.
  • Scopes are checked locally before API invocations to avoid unauthorized requests.
