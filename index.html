Overview

What is HERMES?

HERMES GSuite CLI is a unified Python-based command-line interface designed to bring Google Workspace operations into a terminal-first workflow.

Eliminate Browser Context Switching

Developers and terminal power users spend considerable time context-switching between code editors, shell sessions, and multiple Google Workspace browser tabs. HERMES GSuite CLI connects directly to official Google Workspace APIs so you can triage mail, inspect calendar availability, read spreadsheets, and check meeting agendas without leaving your command-line environment.

Scriptable, Automation-Ready Output

Every HERMES command natively supports human-friendly formatted terminal tables, raw machine-readable JSON, and CSV output. This makes HERMES suitable for shell pipelines with jq, cron jobs, custom bash scripts, developer workflows, and local automation without spinning up cumbersome web frameworks.

Command-Line Application Notice

HERMES is strictly a local command-line interface (CLI) published via PyPI. This website is the official public product information, privacy policy, security documentation, and verification site required for Google OAuth 2.0 app identity. This site is not a browser-based SaaS dashboard or web client.

Authorization Without Passwords

When you initialize HERMES CLI, it initiates Google's standard OAuth 2.0 Installed/Desktop Application flow. Authentication occurs exclusively through Google's official accounts system (accounts.google.com). HERMES never sees, asks for, or stores your Google account password.

You explicitly review and grant permission on Google's consent screen. Google controls the authorization grant, and you can revoke HERMES' access at any time through your Google Account Security dashboard or via the hermes auth logout command.

Authorization Mechanism, Not an Exaggeration

OAuth 2.0 is an industry-standard authorization framework that enables delegated access. We do not claim that OAuth 2.0 automatically makes an application immune to security issues; rather, it ensures that your credentials remain with Google and that access tokens are scoped only to the services you explicitly permit.

Tokens and credentials are held locally under your operating system user account. Read our full Security Documentation for comprehensive technical details.

User-Isolated Credentials

Each user authorizes their own Google account independently. HERMES does not share one developer's Google account or central token pool across users. Tokens are stored exclusively in your local user directory:

Linux/macOS: ~/.config/gsuite-cli/token.json
Windows: %USERPROFILE%\.config\gsuite-cli\token.json

No Intermediary Backend Proxy

Unlike web SaaS services, HERMES does not require a central server to proxy your Google API requests. Your CLI communicates directly over HTTPS with Google's servers (googleapis.com).

Technically Accurate Privacy

We do not make inaccurate marketing claims like "zero data leaves your computer," because Google API requests necessarily transmit command parameters and data to Google's cloud servers to perform operations. What we guarantee is that no data is routed through third-party servers operated by the HERMES project.

AI Integration

AI-Powered Workspace Interaction

HERMES integrates Google Gemini for supported natural-language workflows while keeping direct commands purely deterministic.

Clear Separation: Direct vs. AI Execution

A critical aspect of HERMES' design is that not every command is sent to Gemini. When you run standard commands such as hermes calendar list or hermes sheets read, HERMES executes a direct, deterministic call to the Google Workspace API. No AI processing occurs, and no data is transmitted to Gemini.

Gemini is only invoked when you explicitly execute an AI command (such as hermes ai ask, hermes ai summarize, or hermes calendar smart-create) using your own Gemini API key.

  • Natural-language request interpretation
  • Email summarization and draft assistance
  • Natural-language calendar scheduling
  • Workspace data insights and summaries

Command Processing Pipeline

1. User Command Input: e.g., hermes ai ask "..." vs hermes gmail list
2. Command Processor: Checks if AI flag or ai subcommand is invoked
3. Deterministic Routing:
• Direct Command → Calls Google API directly (no AI)
• AI Command → Sends prompt to Gemini API with user's key
4. Output Display: Formatted table, JSON, or text returned to terminal
Performance

Local Cache for Faster Workspace Operations

HERMES utilizes a local disk cache to accelerate repeated operations and reduce redundant network requests.

TTL-Based Expiration

Cached responses are governed by configurable Time-To-Live (default: 300 seconds / 5 minutes). Cached entries expire automatically, ensuring data remains fresh without manual intervention.

Reduced API Quota Usage

Repeated queries within the TTL window are served directly from your local SQLite-backed disk cache (~/.cache/gsuite-cli/), lowering Google API quota consumption and providing near-instant responses.

Offline-Ready for Supported Reads

We do not claim "fully offline Google Workspace access." However, HERMES is offline-ready for supported cached operations, allowing previously cached reads and calendar summaries to be viewed even during transient network drops.

Getting Started

Install & Authenticate in 3 Simple Steps

No web server to deploy. Install via pip, connect your Google account, and start working.

01

Install HERMES CLI

Install the official package from PyPI into your active Python environment (Python 3.8 – 3.12 supported):

bash 
pip install hermes-cli
02

Authenticate with Google

Provide your Google Cloud Desktop OAuth client credentials (see our OAuth Setup Guide) and run:

bash 
hermes auth login

A browser tab opens to the official Google consent screen where you grant permission to your account.

03

Start Using Workspace Commands

Explore all available operations directly through the integrated help system:

bash 
hermes --help
hermes calendar today
hermes gmail list
