HERMES GSuite CLI Security

This document describes the technical security architecture, credential handling, threat model boundaries, and operational practices of HERMES GSuite CLI.

1. OAuth 2.0 Authorization Model

HERMES GSuite CLI authenticates with Google APIs via the standard OAuth 2.0 for Installed/Desktop Applications framework (RFC 8252).

  • No Password Ingestion: The CLI never receives, prompts for, or processes Google passwords or two-factor authentication secrets.
  • Direct Token Grant: Authentication occurs exclusively through Google's authorization server (accounts.google.com). Tokens are issued directly to the user's local runtime.
  • Delegated Permissions: Access is restricted strictly to the scopes agreed upon by the user during the initial authorization flow.
  • Accurate Security Stance: OAuth 2.0 provides delegated access authorization. It does not eliminate all security risks; users must still maintain the security of their local workstation and the local token storage file.

2. Google Consent Screen

HERMES GSuite CLI adheres strictly to Google's consent screen requirements:

  • Authorization is triggered via an explicit local command (hermes auth login).
  • The user is redirected to Google's official consent interface in their web browser, where Google explicitly lists each requested permission (such as “View and manage your Google Calendar” or “Read, compose, send, and permanently delete all your email from Gmail”).
  • Users must actively verify and approve these permissions before any token is generated.
  • Users can selectively grant or withhold permissions, and HERMES validates whether the required scopes exist before attempting an API call.

3. Local Credential Handling & Storage

HERMES GSuite CLI operates entirely client-side. There is no remote central database or multi-tenant server that aggregates user tokens:

Artifact Storage Path Access Restrictions
OAuth Token (token.json) ~/.config/gsuite-cli/token.json Contains access token, refresh token, expiry, and scope list. Protected by OS user profile permissions.
Client Secret (credentials.json) ~/.config/gsuite-cli/credentials.json OAuth 2.0 Desktop client configuration (Client ID & Client Secret) or environment variable.
Configuration (config.yaml) ~/.config/gsuite-cli/config.yaml CLI user preferences (output styles, default calendar, etc.).
Local Disk Cache ~/.cache/gsuite-cli/ Local SQLite/diskcache database of temporary cached API responses.

On multi-user operating systems, tokens are isolated to the specific OS account running the command. If you wish to revoke tokens immediately, hermes auth logout revokes the active token online with Google and removes token.json from disk.

4. API Communication Security

All network communication initiated by HERMES GSuite CLI is encrypted in transit:

  • Enforced HTTPS: All outgoing API calls use Transport Layer Security (TLS 1.2 or TLS 1.3) over port 443 directly to *.googleapis.com or generativelanguage.googleapis.com.
  • No Intermediary Proxies: Requests travel directly from the user's terminal to Google's infrastructure. No traffic passes through third-party or maintainer-controlled relays.
  • Certificate Validation: Standard certificate authority chains are verified using Python's standard ssl and certifi bundles.

5. Local Cache Architecture

To balance responsiveness with data freshness, HERMES CLI utilizes a local file-based cache powered by diskcache:

  • Configurable Expiration: All cached reads are governed by a strict Time-to-Live (TTL), defaulting to 300 seconds (5 minutes).
  • Hashed Indexing: Cache lookup keys are generated using MD5 hashes of command arguments, preventing query leakage in filenames.
  • Local Purging: Users can run hermes cache clear at any time to immediately purge all cached data from the hard drive.

6. Data Minimization & Direct Execution

HERMES GSuite CLI adheres to data minimization:

  • No Passive Collection: The CLI only queries the specific Google Workspace resources requested by the active command (e.g. running hermes calendar today only requests events for today, not your entire multi-year calendar history).
  • AI Isolation: Google Gemini AI is not executed on standard commands. When running hermes gmail list, no data is sent to Gemini. Only explicit AI subcommands (such as hermes ai ask or hermes ai summarize) send the requested prompt to Google's Gemini API endpoints.

7. Scope Management

HERMES CLI only requests scopes that are tied to implemented functionality. Scopes are requested at authorization time, and the CLI enforces pre-flight scope validation. If a user attempts to execute a command for which authorization was not granted, HERMES halts execution gracefully and notifies the user rather than failing silently or causing inconsistent state.

8. Security Reporting & Vulnerability Disclosure

We welcome vulnerability disclosures and bug reports from the developer community and independent security researchers. If you identify a potential security issue or credential exposure vulnerability:

Responsible Disclosure Guidelines

Please report suspected security vulnerabilities via email to security@yourdomain.com rather than filing public GitHub issues. Please provide reproducible steps and technical details so we can investigate and address the issue promptly.
