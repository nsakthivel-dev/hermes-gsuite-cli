Local Disk Caching Architecture

HERMES GSuite CLI includes a local, persistent disk caching system built on Python's diskcache library to deliver sub-millisecond response times for repeated queries, conserve Google API quotas, and enable offline-ready behavior for supported cached reads.

Storage Location & Isolation

The cache is stored strictly on your local computer under your user home directory:

  • Linux / macOS: ~/.cache/gsuite-cli/
  • Windows: C:\Users\<username>\.cache\gsuite-cli\

The cache uses an embedded, crash-safe SQLite index. Cache entries are isolated by operating system user permissions.

TTL-Based Invalidation

Each cached entry is tagged with a Time-To-Live (TTL). When you execute a query, HERMES checks if an active cache entry exists:

  • Default TTL: 300 seconds (5 minutes).
  • Cache Hit: Returns immediately without issuing a network request to Google APIs.
  • Cache Miss or Expired TTL: Fetches live data from Google APIs, returns the response, and atomically updates the cache.

Offline-Ready Behavior

Accurate Offline Capabilities

We do not claim “fully offline Google Workspace access” because mutating commands (sending emails, modifying spreadsheets, creating meetings) require active communication with Google's cloud servers. Rather, HERMES is offline-ready for supported cached operations: if you disconnect from Wi-Fi or experience network latency, previously cached reads and daily schedule summaries can still be viewed from your local terminal.

Cache Management Commands

HERMES provides built-in commands to monitor and manage local cache state:

Inspect Cache Statistics (hermes cache stats)

bash
$ hermes cache stats
Cache Directory: ~/.cache/gsuite-cli
Total Size: 512.4 KB
Stored Entries: 18
Hit Count: 142
Miss Count: 23
Hit Ratio: 86.1%

Flush Local Cache (hermes cache clear)

To immediately invalidate all cached responses and force fresh fetches from Google:

bash
$ hermes cache clear
✔ Local cache database flushed successfully.
