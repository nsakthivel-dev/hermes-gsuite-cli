Authentication & Google OAuth 2.0

HERMES GSuite CLI follows the BYOC (Bring Your Own Credentials) architecture model. Rather than routing your private data through a shared third-party app, you use Google Cloud OAuth 2.0 Desktop credentials so you retain complete ownership over API access and quotas.

1. Google Cloud Console Setup

To enable HERMES to communicate with your Google Workspace account:

  1. Open the Google Cloud Console.
  2. Create a new project (e.g. Hermes CLI Workspace).
  3. Navigate to APIs & Services → Library and enable the APIs you plan to use:
    • Gmail API
    • Google Calendar API
    • Google Sheets API
    • Google Docs API
    • Google Meet API
    • Google Forms API
    • Google Drive API
    • Google Tasks API
  4. Navigate to APIs & Services → OAuth consent screen:
    • Select External (or Internal for Workspace organizations).
    • Set Application Name to HERMES CLI and provide your email address.
    • Under Test users (if still in testing), add your personal Google account email address.
  5. Navigate to APIs & Services → Credentials:
    • Click Create Credentials → OAuth client ID.
    • Select Application Type: Desktop app.
    • Name it HERMES Desktop Client and click Create.
    • Click Download JSON to save your client secrets file.

2. Supplying Credentials to HERMES

You can provide your client credentials in any of the following ways:

Option A: Default Configuration Path (Recommended)

Copy the downloaded credentials file to the default HERMES configuration directory:

  • Linux / macOS: ~/.config/gsuite-cli/credentials.json
  • Windows: C:\Users\<username>\.config\gsuite-cli\credentials.json

Option B: Environment Variables

Pass the file path or raw secret via shell environment variables:

bash
# Specify file path
export HERMES_GOOGLE_CLIENT_SECRET="/path/to/downloaded-credentials.json"

# Or provide paired client ID & secret
export HERMES_GOOGLE_CLIENT_ID="your-client-id.apps.googleusercontent.com"
export HERMES_GOOGLE_CLIENT_SECRET="your-client-secret"

3. Running the Login Flow

Trigger the OAuth 2.0 authorization process in your terminal:

bash
$ hermes auth login

HERMES launches your default web browser to Google's official accounts page. Review the requested permissions and click Allow. Once granted, Google issues an authorization token, which HERMES saves to:

~/.config/gsuite-cli/token.json
Re-Authenticating & Forcing Scope Updates

If you ever need to re-authorize or expand granted permissions (for example, if you checked only some boxes during initial sign-in), run:
hermes auth login --force

4. Checking Token Status

To view your active token status, scope grants, and expiration timestamps:

bash
$ hermes auth status
OAuth Status: Authenticated (Valid)
Account: user@example.com
Token File: ~/.config/gsuite-cli/token.json
Token Expiry: 2026-09-27 12:45:00 UTC (Auto-refreshed via refresh_token)
Scopes:
  - https://www.googleapis.com/auth/calendar
  - https://www.googleapis.com/auth/gmail.modify
  - https://www.googleapis.com/auth/spreadsheets
  - https://www.googleapis.com/auth/documents
  - https://www.googleapis.com/auth/meetings.space.created
  - https://www.googleapis.com/auth/forms.body

5. Logging Out & Token Revocation

To safely invalidate your authorization and delete local credentials:

bash
$ hermes auth logout
✔ Token revoked with Google accounts
✔ Local token removed from ~/.config/gsuite-cli/token.json
